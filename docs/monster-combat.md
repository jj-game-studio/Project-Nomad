# 근접 잡몹 전투 테스트

- 작업: #38, 상위 #17. 공통 피해/플레이어 사격은 병합된 #15를 사용합니다.
- 현재 범위: 잡몹·엘리트 전투, 테스트 스폰창과 피격 표시. 해골 무료4종 잡몹 외형 연결은 [몬스터 외형](monster-appearance.md), 생성 필드 연결은 [통합 게임플레이](gameplay-integration.md)를 참고합니다. 지정 보스Golem/엘리트Necromancer 파일과 보스전·드롭은 후속 범위입니다.
- 최신 탐지 규칙(2026-11-16):방향 구분 없는 원형 반경, 벽/지형 차폐 유지. 일반8m/엘리트10m 기본값이며 패널에서 조절합니다. 아래의 시야각/근접 원 설명은 이전 구현 이력이고, 현재 규칙은 마지막의 원형 탐지 절을 따릅니다.

## 직접 플레이

Unity 6000.6.9f1에서 `Nomad > Monsters > Create Combat Preview`로 전용 씬을 만들고,
`Nomad > Monsters > Open Playable Combat`으로 열어 Play합니다. 저장된 `Assets/Nomad/Monsters/MonsterCombat.unity`를 직접 열어도 됩니다.
생성 메뉴는 이 전용 씬만 다시 만드므로 수동으로 편집했다면 별도로 저장합니다.

Game 화면 클릭 후 WASD 이동, 좌클릭 사격, Shift 구르기, Space 점프, R 또는 Restart 버튼으로 재시작합니다.
파란 캡슐은 플레이어, 초록 캡슐은 몬스터입니다. 몬스터가 주황색이면 공격 준비 중이며 회색이면 사망 상태입니다.
화면에서 양쪽 HP와 공격 단계를 확인할 수 있습니다. 재시작은 전용 씬의 개체·발사체·체력을 함께 다시 로드합니다.

## 동작 흐름

추적 → 1.8m 이내·시야 확보 → 이동을 멈추고 0.5초 준비 → 거리·벽·생존 여부 재확인 → 공통 피해 1회 → 1초 대기 → 추적 재개.

- 준비 중 범위를 벗어나거나 벽이 생기면 빗나갑니다. 빗나가거나 무적으로 막아도 공격 후 대기는 적용합니다.
- 피해는 `Health.TryApplyDamage`로만 전달합니다. 플레이어의 구르기 전투 무적을 기존 계약대로 적용합니다.
- 몬스터 사망 시 준비된 공격을 취소하고 추적·이동을 중단합니다. 플레이어가 죽어도 추적·공격을 중단합니다.
- 플레이어 사격은 기존 `PlayerCombat`와 `PlayerProjectile.prefab`을 그대로 사용합니다. 몬스터 루트의 충돌체가 공통 Health로 피해를 전달합니다.
- 적 시체는 회색 도형으로 남습니다. 시체 제거·전리품·런 초기화는 포함하지 않습니다.

## 임시 설정

양쪽 최대 HP 100, 잡몹 근접 피해20/거리1.8m/준비0.5초/타격 후 대기1초입니다.
플레이어 사격은 #15의 기존 피해25·발사체 속도45m/s를 유지합니다.
근접 공격 수치는 MonsterMeleeAttack Inspector에서 조정할 수 있으며 최종 밸런스 확정이 아닙니다.

## 자동 검증

별도 작업 사본의 루트에서 `./scripts/Test-MonsterTracking.ps1`로 기존 추적 검사와 신규 근접 검사를 함께 실행합니다.
신규 검사만 실행하려면 `-TestFilter 'Nomad.Monsters.Tests.MonsterMeleeAttackTests'`를 붙입니다.
결과 XML과 원본 로그는 실행별 `UnityProject/Artifacts/tests/monster-tracking/`에 저장하며 실행기는 완료 후 실패만 요약합니다.

신규 검사는 준비/단일 타격/대기, 준비 중 이탈·벽 차단, 전투 무적 계약, 양쪽 사망 시 공격 취소, 기존 공개 사격 함수와 공통 발사체를 통한 몬스터 사망을 확인합니다.
사격 통합 검사는 PlayerCombat.TryShoot를 호출하고 실제 발사체의 충돌·피해·사망을 확인합니다. 플레이어가 기본 Assembly-CSharp에 있어 공개 함수를 리플렉션으로 호출하며 플레이어 어셈블리는 재편하지 않습니다.
헤드리스 Test Runner의 합성 마우스 상태가 초기화되는 현상을 확인해 입력 경로의 새 검증으로 보고하지 않습니다. 좌클릭 입력 경로는 #15의 기존 검증을 활용하며 실제 조작감은 사람이 확인합니다.
무적 계약 검사는 Health의 무적 상태를 설정합니다. 실제 Shift 입력의 구르기 시작/종료는 #15의 기존 검증 범위이며 이번 계약 검사와 구분합니다.
엘리트/보스 패턴·생성 필드·Windows 플레이어 빌드와 사람의 조작감·수치 수용 여부는 이 자동 검사에 포함하지 않습니다.

2026-11-15 Unity 6000.6.9f1 / Windows의 별도 작업 사본에서 추적8개+전투7개, 총15개가 통과했습니다.
실행기 결과는 실패0/건너뛰기0/종료코드0이며 요약된 로그 예외도 없습니다.
검증 중 화면 표시의 MaterialPropertyBlock 초기화를 Awake로 옮기고, 공격 중단 시 ResetPath 뒤에 isStopped를 설정하도록 수정했습니다.
NUnit 실패 메시지의 CDATA를 형식명 대신 실제 텍스트로 표시하도록 실행기도 보완했습니다.

## 엘리트 변형 (#53)

`Nomad > Monsters > Create Elite Preview`로 별도 `MonsterElite.unity`를 생성하고,
`Nomad > Monsters > Open Playable Elite`로 열어 Play합니다. 잡몹 전용 씬은 그대로 유지합니다.
엘리트는 보라색의 큰 임시 도형과 HP250으로 구분합니다. 외형 구분만 추가하며 기존 통행·공통 피해 계약은 바꾸지 않습니다.

기본 공격2회 시도 → 강공격1회 시도를 반복합니다. 공격이 빗나가거나 무적으로 막혀도 시도 순서는 진행합니다.
기본 공격은 기존20피해/0.5초 준비/1초 대기를 유지하고, 강공격은40피해/1.2초 준비/1.8초 대기입니다.
강공격은2.6m/정면90도이며 준비 시작 방향을 고정합니다. 붉은 몸체와 바닥 부채꼴 경고가 나타나면 옆으로 피하거나 범위 밖으로 이동합니다.
타격 시 거리·방향·벽·생존 여부를 다시 확인하고, 사망하면 진행 중인 강공격과 경고를 취소합니다. 회복 대기 중에는 추가 피해가 없습니다.
이 수치는 테스트용으로 Inspector에서 조정할 수 있으며 최종 난이도나 아트 방향의 승인이 아닙니다.

`MonsterMeleeAttack.enableHeavyAttack`의 기본값은 false입니다. 엘리트 씬에서만 켜고 같은 체력·추적·근접 상태 전환을 재사용합니다.
기존 잡몹 씬/기본 설정은 강공격을 사용하지 않습니다. 몸체·경고 표시와 화면 안내도 같은 Demo를 재사용합니다.

엘리트 검사만 실행하려면 `./scripts/Test-MonsterTracking.ps1 -TestFilter 'Nomad.Monsters.Tests.MonsterEliteTests'`를 사용합니다.
새 검사는 기본2회/강1회 순서와 단일40피해·긴 회복, 방향 고정 및 측면 회피, 범위 이탈, 벽 차단, 전투 무적, 사망 취소를 확인합니다.

2026-11-15 Unity 6000.6.9f1 / Windows에서 기존15개+엘리트6개, 총21개 통과/실패0/건너뛰기0/종료코드0을 확인했습니다.
실행기 요약의 로그 예외도 없었습니다. 사람의 강공격 가독성·피해·회피 난이도 수용 판단은 별도로 남깁니다.

## 분할 체력바와 공격 준비 채움

일반몹과 엘리트 체력은 각 몬스터 머리 위의10칸 체력바로 표시합니다. 엘리트 HP250 기준 한 칸25, 잡몹 HP100 기준 한 칸10이며, 부분 피해도 마지막 칸 내부의 비율로 표시합니다. 월드 위치를 카메라 화면 좌표로 변환해 이동을 따라가며 사망/화면 밖/카메라 뒤에서는 숨깁니다. 보스 HUD는 별도 후속 범위로 이 컴포넌트를 붙이지 않습니다.
공격 범위의 외곽선은 실제 사거리로 고정하고, 안쪽의 반투명 영역이 중심에서 바깥으로 차오릅니다. 기본 공격은 원형, 강공격은 부채꼴입니다.
화면의 준비 퍼센트와 채움은 모두 `MonsterMeleeAttack.WindupProgress`를 읽습니다. 별도 표시 타이머를 사용하지 않습니다.
진행도100%인 프레임을 표시한 다음 타격하며, 타격 후/취소/사망 시 범위 채움을 지웁니다. 준비 완료 시에도 거리·방향·벽·생존 여부를 재검사합니다.

`MonsterMeleeAttack.AttackSpeed`는 기본1배이며 Inspector에서 조정할 수 있습니다. 2배면 준비·채움·회복이 두 배 빠르고 0.5배면 절반 속도입니다.
준비 중 배율을 바꿔도 누적 진행도를 유지한 채 새 속도로 이어집니다. 기본 피해량·강공격 순서·사거리에는 영향을 주지 않습니다.
진행도 기준으로 바뀌면서 기존 준비 시간에 표시용 최대1프레임이 더해집니다. 기본 공속1에서 기존 전투/추적 회귀 검사를 유지합니다.

2026-11-15 추가 표시/타이밍 검사6개를 포함해 총27개 통과/실패0/건너뛰기0/종료0을 확인했습니다.
추가 검사는 분할/부분 HP, 채움과 실제 피해 동기화, 공속2배, 준비 중 공속 변경, 부분 채움 중 사망 취소, 원형/부채꼴 메시 구분입니다.

## 현재 감지·이동 규칙과 후속 제안

아래는 테스트 스폰창 추가 전의 공통 기본값입니다. Tracker 기본값은 유지하며, 현재 전용 테스트 씬의 개체에는 아래 스폰창의 종류별 임시 설정을 적용합니다.
- 감지: 전방120도/8m 시야 또는 주변2m. 둘 다 벽에 가리면 감지하지 않습니다.
- 추적: NavMesh 경로로3.5m/s 이동. 0.2초마다 마지막 목격 지점으로 경로 갱신, 접근 정지거리1.2m. 공격 준비/회복 중에는 정지합니다.
- 포기: 몬스터와 대상 사이12m 초과 또는 시야 상실2초. 시야가 없을 때 실제 대상 위치를 따라가지 않고 마지막 목격 지점까지만 이동합니다. 끊긴 경로는 직선으로 관통하지 않고 멈춥니다.
- 아직 없는 동작: 스폰 기준 활동 반경, 스폰 복귀, 비전투 순찰. 현재 포기하면 그 자리에서 대기하므로 계속 유인하면 스폰에서 멀어질 수 있습니다.

후속 제안이던 활동 반경과 복귀는 아래 테스트 스폰창 요청에서 테스트용으로 구현했습니다. 잡몹은 감지8m/120도·근접2m/대상 거리12m/스폰 활동반경15m. 엘리트는 감지10m/140도·근접3m/대상 거리16m/스폰 활동반경20m. 반경 이탈 또는 추적 포기 시 NavMesh로 스폰 복귀→도착 후 재감지합니다. 복귀 도중에는 재감지하지 않고 체력을 회복하지 않습니다. 이동 프레임의 작은 경계 초과는 복귀로 처리하며 반경을 물리 벽처럼 막지는 않습니다. 순찰/보스 전투 구역은 미구현입니다. 임시 수치는 최종 게임 규칙의 승인을 의미하지 않습니다.

## 테스트 스폰창과 동작 로그

`Nomad > Monsters > Open Playable Elite` 또는 `Open Playable Combat`에서 사용합니다. 일반/엘리트1마리로 시작하며 오른쪽 위 패널에서 추가 소환할 수 있습니다. 화면이 작으면 패널을 비례 축소하고 내부 스크롤을 제공합니다.

- Normal/Elite/Boss 선택. 종류별 설정은 별도로 유지됩니다. Boss는 미구현 안내만 표시하고 소환/적용을 막습니다.
- 이동속도, 시야 거리/각도, 근접 감지, 대상과의 거리 제한, 스폰 기준 활동 반경, 공속, 공격 거리, 최대 HP, 피해량을 조절합니다. 엘리트는 강공격 거리/피해량도 조절합니다.
- `Place on floor...` 후 바닥 클릭으로 소환, Esc로 취소합니다. 또는 플레이어 전방5m 소환 버튼을 사용합니다. NavMesh와 실제 충돌을 검사하여 벽·캐릭터·다른 몬스터 위나 필드 밖 배치를 거절합니다. 최대12마리이며 죽은 개체도 제거 전까지 개수에 포함합니다.
- 목록에서 몬스터를 선택하고 `Apply settings + reset selected`를 누르면 해당 개체만 원래 스폰 위치에 새 설정/최대 체력으로 재생성합니다. 즉시 전투 중 밸런스를 바꾸기보다 동일 초기 조건을 비교하는 기능입니다. 위치가 막히면 기존 개체를 보존합니다. 종류가 다르면 적용을 막습니다.
- 선택 제거/전체 제거, 종류별 기본값 복원, 플레이어 회복·부활, 전투 무적, 일시정지/재개, R재시작을 제공합니다. 무적은 낙하 피해를 막지 않습니다. 회복·부활은 위치를 이동시키지 않습니다.
- 감지 토글: 옅은 청록 시야 부채꼴, 초록 근접 원. 이동 토글: 몬스터 중심의 주황 대상 거리 원, 스폰 위치 중심의 보라 활동 반경 원. 모두 실제 Tracker 값에서 그리며, 공격 준비 채움은 기존대로 별도로 표시합니다.
