# 근접 잡몹 전투 테스트

- 작업: #38, 상위 #17. 공통 피해/플레이어 사격은 병합된 #15를 사용합니다.
- 범위: 기본 도형 잡몹 1종의 공격·피해·사망. 엘리트·용·드롭·생성 필드 배치와 실제 어셋은 후속 작업입니다.

## 직접 플레이

Unity 6000.6.9f1에서 `Nomad > Monsters > Create Combat Preview`로 전용 씬을 만들고,
`Nomad > Monsters > Open Playable Combat`으로 열어 Play합니다. 저장된 `Assets/Nomad/Monsters/MonsterCombat.unity`를 직접 열어도 됩니다.
생성 메뉴는 이 전용 씬만 다시 만드므로 수동으로 편집했다면 별도로 저장합니다.

Game 화면 클릭 후 WASD 이동, 좌클릭 사격, Shift 구르기, Space 점프, R 또는 Restart 버튼으로 재시작합니다.
파란 캡슐은 플레이어, 초록 캡슐은 몬스터입니다. 몬스터가 주황색이면 공격 준비 중이며 회색이면 사망 상태입니다.
화면에서 양쪽 HP와 공격 단계를 확인할 수 있습니다. 재시작은 전용 씬의 개체·발사체·체력을 함께 다시 로드합니다.

## 동작 흐름

추적 → 1.8m 이내·시야 확보 → 이동을 멈추고 0.5초 준비 → 거리·벽·생존 여부 재확인 → 공통 피해 1회 → 1초 대기 → 추적 재개.

- 준비 중 범위를 벗어나거나 벽이 생기면 빗나갑니다. 빗나가거나 무적으로 막아도 공격 후 대기는 적용합니다.
- 피해는 `Health.TryApplyDamage`로만 전달합니다. 플레이어의 구르기 전투 무적을 기존 계약대로 적용합니다.
- 몬스터 사망 시 준비된 공격을 취소하고 추적·이동을 중단합니다. 플레이어가 죽어도 추적·공격을 중단합니다.
- 플레이어 사격은 기존 `PlayerCombat`와 `PlayerProjectile.prefab`을 그대로 사용합니다. 몬스터 루트의 충돌체가 공통 Health로 피해를 전달합니다.
- 적 시체는 회색 도형으로 남습니다. 시체 제거·전리품·런 초기화는 포함하지 않습니다.

## 임시 설정

양쪽 최대 HP 100, 잡몹 근접 피해20/거리1.8m/준비0.5초/타격 후 대기1초입니다.
플레이어 사격은 #15의 기존 피해25·발사체 속도45m/s를 유지합니다.
근접 공격 수치는 MonsterMeleeAttack Inspector에서 조정할 수 있으며 최종 밸런스 확정이 아닙니다.

## 자동 검증

별도 작업 사본의 루트에서 `./scripts/Test-MonsterTracking.ps1`로 기존 추적 검사와 신규 근접 검사를 함께 실행합니다.
신규 검사만 실행하려면 `-TestFilter 'Nomad.Monsters.Tests.MonsterMeleeAttackTests'`를 붙입니다.
결과 XML과 원본 로그는 실행별 `UnityProject/Artifacts/tests/monster-tracking/`에 저장하며 실행기는 완료 후 실패만 요약합니다.

신규 검사는 준비/단일 타격/대기, 준비 중 이탈·벽 차단, 전투 무적 계약, 양쪽 사망 시 공격 취소, 기존 공개 사격 함수와 공통 발사체를 통한 몬스터 사망을 확인합니다.
사격 통합 검사는 PlayerCombat.TryShoot를 호출하고 실제 발사체의 충돌·피해·사망을 확인합니다. 플레이어가 기본 Assembly-CSharp에 있어 공개 함수를 리플렉션으로 호출하며 플레이어 어셈블리는 재편하지 않습니다.
헤드리스 Test Runner의 합성 마우스 상태가 초기화되는 현상을 확인해 입력 경로의 새 검증으로 보고하지 않습니다. 좌클릭 입력 경로는 #15의 기존 검증을 활용하며 실제 조작감은 사람이 확인합니다.
무적 계약 검사는 Health의 무적 상태를 설정합니다. 실제 Shift 입력의 구르기 시작/종료는 #15의 기존 검증 범위이며 이번 계약 검사와 구분합니다.
엘리트/보스 패턴·생성 필드·Windows 플레이어 빌드와 사람의 조작감·수치 수용 여부는 이 자동 검사에 포함하지 않습니다.

2026-11-15 Unity 6000.6.9f1 / Windows의 별도 작업 사본에서 추적8개+전투7개, 총15개가 통과했습니다.
실행기 결과는 실패0/건너뛰기0/종료코드0이며 요약된 로그 예외도 없습니다.
검증 중 화면 표시의 MaterialPropertyBlock 초기화를 Awake로 옮기고, 공격 중단 시 ResetPath 뒤에 isStopped를 설정하도록 수정했습니다.
NUnit 실패 메시지의 CDATA를 형식명 대신 실제 텍스트로 표시하도록 실행기도 보완했습니다.
