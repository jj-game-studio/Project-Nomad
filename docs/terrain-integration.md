# 지형 통합 테스트와 WFC 생성

## 유지 기준

모든 지형 **통합 테스트의 기준 씬**은 `Assets/Nomad/Terrain/Wfc/TerrainIntegration.unity`입니다. `Nomad > Terrain > Open Integration Test Scene`으로 엽니다. 앞으로 지형 원형·생성 규칙·소품/경로 소비·플레이어 시작점 등 지형 통합에 영향을 주는 변경은 이 씬과 자동 검증도 함께 갱신하고, 이 씬에서 검증한 결과를 해당 Issue/PR에 기록해야 합니다.

- 씬을 새로 만들거나 카탈로그를 다시 구울 때는 `Rebuild Integration Test Scene`을 사용합니다. 재구성은 이 씬을 다시 저장하므로 수동 편집을 보존하려면 먼저 별도로 저장합니다.
- 기존 #50의 타일 단독 장면은 원형 편집/단위 확인용입니다. 통합 완료 근거는 이 씬으로 제출합니다.
- 정적 검사 진입점은 `TerrainIntegrationValidation.Run`, 실제 Play 입력/프레임 검사는 `TerrainIntegrationPlayVerification.Run`입니다. 둘 다 같은 저장 씬을 엽니다. 독립적인 원형 수치 검사는 임시 물리 씬을 사용합니다.

## 조작

Play 후 Game 탭을 클릭합니다. R=새 seed, T=현재 seed 재현, L=WFC/기존 연결 생성 비교, P=소품 배치 토글, O=생성 필드 전체 보기/플레이어 카메라, G=108개 코너 조합+신규 ㄷ/ㄴ 원형4종 갤러리/플레이어 카메라입니다. WASD/Space/왼쪽 Shift로 이동하며 추락하면 시작점으로 복귀합니다. HUD에 seed·생성 성공/실패·타일/소품 수·시도와 후보 검사 수를 표시합니다.

초기 WFC는 6×6 타일입니다. Inspector의 `Terrain Integration Controls`에서 seed·가로·세로(각3~16)를 설정할 수 있습니다. 구형 비교는 기존 구매 에셋 타일 9종과 12개 조각을 사용하므로 등록된 비공개 서브모듈이 필요합니다. 실제 필드 Ready/NavMesh 제공은 #18, 몬스터/상자 통합은 해당 후속 Issue 범위이며 이 씬은 아직 그 기능을 완료했다고 표시하지 않습니다.

## WFC 방식

`WfcTerrainCatalog`는 원형/코너 조합/90도 회전을 별도 후보로 저장합니다. #50의 십자81·T자27·넓은 일자 계단1, 신규 ㄷ/ㄴ 볼록·오목4종과 낮은/높은 평지를 포함하며 90도 회전까지 총460후보입니다. 원형 수와 논리 후보 수는 다릅니다. 모든 코너 조합을 후보로 등록하지만 주변 제약과 경계에 맞지 않는 후보는 전파 과정에서 제거됩니다.

1. 모든 셀에 후보 집합을 넣고 시작 셀은 낮은 평지, 3×3 이상 중앙 셀은 계단으로 제한합니다.
2. 계단의 필수 출입구와 맵 경계를 먼저 검사합니다.
3. 이웃과 호환 가능한 상대 후보가 없는 항목을 제거하고, 변화가 있으면 다시 전파합니다.
4. 후보 수가 가장 적은 셀을 골라 가중 무작위로 하나를 선택합니다. 같은 seed·원형/규칙·설정에서는 같은 결과가 나옵니다.
5. 모순이나 연결 실패는 최초+3회 재시도 후 실패 결과를 내고 부분 지형을 정리합니다. 후보 비교는 전체 생성당 최대2,500만회로 제한합니다.

평지/높은 평지끼리는 대응 높이가 같아야 합니다. 일반 계단끼리는 변 공유를 금지하고 넓은 계단이 한쪽이라도 있으면 인접을 허용합니다. 대각선 인접은 금지하지 않습니다. 계단 팔/넓은 계단의 고정 입출구는 폭2m 지지 샘플과 대응 높이 바닥이 필요하며 맵 밖으로 향할 수 없습니다. 첫 단의 0.25m 단차는 허용합니다. 코너를 포함한 변 전체를20개 지점으로 비교해 양쪽 바닥 높이가 최대0.25m 차이만 나도록 합니다. 비어 있는 각 영역은 실제 맵 외곽에 닿아야 하며 맵 내부 구멍은 허용하지 않습니다. 이전의 코너 임의 높이/내부 구멍 허용 선택은 사용자 피드백으로 대체되었습니다.

카탈로그는 원형의 실제 Collider에서 변의 -3.5/0/3.5m 통로와 폭2m 내부, 변당20개 높이 샘플과20×20 표면의 빈 영역 연결 성분을 읽어 만듭니다. 원형 아트/충돌을 바꾼 뒤에는 반드시 카탈로그와 씬을 재구성하고 통합 검증을 다시 실행해야 합니다. 인접 높이 규칙의 자동 통과는 모든 표면의 NavMesh 도달성 검증을 대신하지 않습니다.

## 복층 금지

WFC의 셀 간 간격은10m이며 XZ셀당 원형 하나만 배치합니다. 모든 원형의 기준 Y는 동일하고 위에 새 타일을 쌓지 않습니다. 낮은/높은 바닥(0/2m)과 계단은 원형 자체의 형상으로 표현합니다. 구형 연결 생성에도 `TerrainGenerator.FootprintsOverlap`을 적용하여 Y가 달라도 XZ 발자국이 겹치면 배치를 거부합니다. 따라서 낮은 바닥을 남긴 채 그 위에 새 조각을 놓는 형태는 허용하지 않습니다.

각 원형 자체에도 같은 XZ 위치의 보행 표면이 두 층으로 겹치지 않아야 합니다. 이후 구매 에셋 적용 시에도 이 규칙을 유지하고 카탈로그 재구성·표면 검사·같은 씬의 플레이 검토를 다시 해야 합니다. 복층 금지와 다른 높이의 인접 지형/절벽은 별개입니다.

## 결과 계약과 범위

`TerrainGenerator.ConfigureWfc`가 새 경로를 선택하며, 기존 `Configure`는 구형 비교/회귀 경로를 선택합니다. `TerrainGenerationResult`, 세대 ID, 시작/완료 이벤트와 기존 `PropScatter` 소비 계약은 유지합니다. 후보 확정 전에는 게임 오브젝트를 배치하지 않고, 최종 지형도 완료까지 비활성 상태로 구성합니다.

씬·카탈로그·신규 평지 원형은 공개 프로젝트의 기본 Cube와 공유 메시만 사용합니다. 구매 에셋 원본/기존 지형 프리팹은 비공개 서브모듈에 유지합니다. Windows 플레이어 빌드·#18 경로 제공·몬스터/전투·실제 상자 입력 연결은 이번 변경의 완료로 간주하지 않습니다. 생성 품질과 고저차의 최종 수용은 사람 검토가 필요합니다.

## 플레이 피드백 반영: 코너·빈 영역·ㄷ/ㄴ자 계단 (2026-11-16)

이미지1의 높은 코너/낮은 이웃 불일치는 고정 계단 출입구만 검사하던 규칙이 원인이었습니다. 이제 양쪽 변 전체 높이를 검사하여 코너도 주변 높이에 맞는 조합만 선택합니다. 이미지2의 T자 빈 영역은 내부 후보에서 제외합니다. 원형의 각 빈 연결 영역이 실제 맵 외곽에 닿는 후보만 허용하며, 완성된 필드의 빈 영역을 실제 Collider에서 다시 읽고 외곽부터 flood fill해 내부 구멍이 없는지도 검증합니다. 테두리 T자 빈 영역은 허용하는 양의 사례도 확인합니다.

새 원형은 기존0/2m 높이·0.25m 단·10×10m 범위를 유지합니다.

| 원형 | 빨간 평지 영역에 대응하는 부분 | 계단 |
| --- | --- | --- |
| WideUHigh | 중앙4×7m, 높이2m | 서·남·동의3m 띠가 주변0m로 연결 |
| WideULow | 같은 중앙 영역, 높이0m | 같은 ㄷ자 띠가 주변2m로 연결 |

볼록/오목 의미는 사용자 확인을 받았습니다. 모서리의 계단 띠도 연속되며 새 원형은 전체 폭 계단 인접 예외에 포함됩니다. 모든 출입구 바닥 지지와 수직 적층 금지는 유지합니다. 계단 띠는 원형당 공유 메시1개로 결합하고 중앙 평지와 함께 Renderer2개로 표현합니다. 원형별 Collider는 계단 단과 중앙 바닥을 따릅니다. 아트/이동감 최종 수용을 확정한 것은 아닙니다.

같은 통합 씬의 G 갤러리에는 기존108조합 뒤에 새4종이 있습니다. Hierarchy에서 WideUHigh/WideULow/WideLHigh/WideLLow를 선택하고 Scene 뷰에서 F키로 확대해 확인할 수 있습니다. 생성 규칙이 바뀌었으므로 보완 전과 동일 seed라도 배치는 달라집니다. 같은 최신 버전/설정에서의 재현성은 유지합니다.
