# 3m 지형과 단일 통합 테스트

현재 이 저장 통합씬에는 플레이어 사격·체력, 기존 E키 루팅, 일반/엘리트 전투와 사망/런 재시작도 연결되어 있습니다. `Nomad > Gameplay > Open Integrated Gameplay`로 바로 실행합니다. 일반 플레이 HUD와 F1 진단 표시, 검증 결과 및 부족한 게임 루프는 [통합 게임플레이](gameplay-integration.md)를 참고합니다.

조명·포스트 프로세싱·Kingdom 식생/엄폐물 꾸밈은 별도 `TerrainTest` 씬에서 검토합니다. [TerrainTest 씬과 필드 꾸밈](terrain-dressing.md)을 참고합니다.

## 현재 규격

- 생성 단위는 **3×3m 정사각형**입니다. 기존10m 원형을 단순 축소하는 대신 평지·직선 계단·볼록/오목 코너로 재구성합니다.
- 평지 높이는 실제 **0/1/2m**입니다. 계단은0↔1m 또는1↔2m, 한 단은0.25m입니다. 한 셀에 원형 하나만 놓으며 수직 복층/바닥 구멍은 만들지 않습니다.
- 평지3종,1/2m 절벽2종, 높이 구간별 직선/볼록/오목 계단6종으로 원형11개입니다. 회전을 포함한 WFC 후보는29개입니다.
- `MicroTerrainTile`의 연속 높이와 단 높이를 기준으로 메시/Collider/연결 데이터를 제작합니다. 계단·코너는 작은 조각을 조합해 ㄷ자/ㄴ자 등으로 이어집니다.
- 이전10m/0·2m 원형은 비교·단위 회귀용으로 보존합니다. 현재 생성은 `Micro/MicroCatalog.asset`을 사용합니다.

## 유지 기준과 실행

모든 지형 **통합 테스트의 기준 씬**은 `Assets/Nomad/Terrain/Wfc/TerrainIntegration.unity`입니다. `Nomad > Terrain > Open Integration Test Scene`으로 엽니다. 지형 원형·규칙·소품/경로 소비·시작점 등 통합에 영향을 주는 변경은 이 씬과 검증도 함께 갱신하고 해당 Issue/PR에 결과를 기록해야 합니다.

`Rebuild Integration Test Scene`은 현재3m 원형·카탈로그와 같은 씬의 참조를 갱신합니다. 수동 변경은 먼저 저장합니다. 최초 씬이 없을 때만 기본 검토 구조를 만들고3m 설정을 적용합니다. 이전 타일 단독 장면은 편집·단위 확인용이며 통합 완료 근거를 대신하지 않습니다.

Play 후 Game 탭을 클릭합니다.

| 입력 | 동작 |
| --- | --- |
| R / T | 새 seed 생성 / 현재 seed 재현 |
| O | 전체 필드 보기 / 플레이어 카메라 |
| G | 작은 원형11종 갤러리 / 플레이어 카메라 |
| L | 기존9종 원형 연결 생성과 비교 /3m 생성 복귀 |
| P | 검토용 소품 배치 토글 |
| WASD / Space / 왼쪽 Shift | 이동 / 점프 / 구르기 |

HUD에는 seed·상태·타일/소품 수·후보 검사·도달성 검사 수와 출구 수/방향을 표시합니다. 입구 쪽을 뺀 3면의 초록 기둥이 임시 출구이며, 들어가면 `Exit reached`가 표시됩니다([생성 필드 경로](field-navigation.md)의 출구 절). 추락하면 안전 시작점으로 돌아갑니다. 기본 크기는18×18=324조각, 약54m 정사각형입니다. Inspector의 Terrain Integration Controls에서 seed·가로·세로를 조절합니다(도구12~24, 생성 API12~32).3단계의 안전한 평지·계단 간격을 확보하기 위해 최소12개 셀을 요구합니다.

## 높이 골격과 WFC

완전히 독립적인 높이를 무작위로 선택하면 절벽에 둘러싸인 고립 타일이 생기기 쉽습니다. 먼저 연결된0/1/2m 높이 골격을 정하고, 그 골격에 맞는 원형/회전 후보를 WFC에 넣습니다. 중앙 고정 고원 대신 seed별로 굽이치는 두 높이 경계와 방향·높낮이 반전을 정합니다. 경계는3~5행마다 꺾이고 높이 구간 사이에는 평지를 남깁니다. 자유로운 임의 지형을 모두 탐색하는 방식은 아닙니다.

WFC는 후보 전파·최소 후보 셀 선택·가중 선택을 유지합니다. 직선 경계는65% 확률로 절벽을 선택하고 나머지는 계단으로 연결합니다. 일정 간격의 계단과 강제2→0m 절벽 연장은 제거했습니다. 실제 도달성 검사가 모든 높이 구역의 우회 연결을 확인합니다. 최초+3회 재시도, 후보 비교2,500만회 상한으로 유한 종료합니다. 공간·접합·도달성 실패 시 부분 지형을 공개하지 않습니다. 같은 버전·seed·설정에서는 재현되지만 이전 규격의 배치와 같지는 않습니다.

- 일반 접합은 변 전체20개 높이 샘플을 비교합니다. 계단 첫 단의0.25m 차이는 허용합니다.
- 공유 변 양쪽 계단이 모두 변을 향해 오르거나 내려가면 ^/V로 판단해 거부합니다. 측면에서 반대로 향하는 계단도 높이 프로파일로 거부합니다.
- 같은 방향의0→1→2m 연속 오르막은 허용합니다. 볼록/오목 코너의 연속 측면 접합도 허용합니다.
- 계단의 평평한 입출구는 대응 높이 바닥이 있어야 합니다. 높은 절벽 벽으로 끝나는 계단 출입구는 허용하지 않습니다.

## 절벽과 벽

절벽은1m/2m의 평평한 원형입니다. 같은 높이와 낮은 평지/절벽에 인접할 수 있습니다. 높이 차 경계는 직결 보행 경로로 취급하지 않고 별도 계단으로 우회합니다.

최신 사용자 피드백에 따라 낙하 경계와 맵 외곽의 벽은 생성하지 않습니다. 절벽 낙하와 맵 밖 이탈이 가능하며 기존 추락 복귀를 유지합니다. `MicroTerrainWalls`는 이전 구현 기록으로 보존하지만 생성과 검증 fixture에서 호출하지 않습니다.

## 모든 타일 도달성

타일 연결점 그래프만으로 성공을 판단하지 않습니다. 실제 타일 BoxCollider를 반지름0.35m/높이1.8m/단차0.3m/경사45도 캐릭터의 NavMesh로 굽습니다. 각 타일의3×3 대표 지점에 대해 시작점에서 완전한 보행 경로가 있는지 검사합니다. 중앙 상자를 포함한 재검사에서는 평지의 표본을 중심에서±1.1m로 넓히고 상자 안의 중앙 표본만 제외하여 주변8지점의 우회 공간을 확인합니다. 시작 표본도 실제 표면 높이를 사용합니다. 점프/낙하 링크로 고립 지형을 임의 연결하지 않습니다.

기본324타일은 생성당2,916개 경로를 검사합니다.3m 원형 자체는 빈 영역 없는 연속 표면이며 여러 지점을 검사해 타일 내부의 연결도 확인합니다. 실패하면 재시도하고, 끝내 실패하면 타일/링크를 비우고 실패 상태를 반환합니다.

통합 씬은 소품 배치 후에도 같은 경로 검사를 다시 실행합니다. 경로를 막은 위치의 소품을 제거하고 재검사하며, 가까운 소품이 없으면 수량을 줄이는 유한 정리를 합니다.16회 내에 회복되지 않으면 소품을 제외해 재검사합니다. 최종 도달성/안전 시작점이 확인되기 전에는 플레이어를 활성화하지 않습니다. 같은 seed의 소품 정리 결과도 재현됩니다. 안전성에 따라 소품 수가 줄어들 수 있습니다.

지형 후보 검사의 NavMesh는 검사 후 제거합니다. 최종 소품 반영 뒤에는 #18의 `FieldNavigation`이 지속 NavMesh와 `Ready/Failed` 결과, 적·상자 후보를 제공합니다. 통합 씬은 최종 Ready 이후에만 플레이어를 활성화하며 HUD에 상태와 후보 수를 표시합니다. 재생성/종료 시 이전 결과와 NavMesh를 무효화합니다. 소비 계약과 검증 방법은 [생성 필드 경로](field-navigation.md)를 참고합니다. 패키지는 공식 레지스트리의 `com.unity.ai.navigation@2.0.16`을 사용합니다.

## 소품과 기존 계약

기존 `TerrainGenerationResult`, 세대 ID·시작/완료 이벤트, 기존 `PropScatter.Configure`와 통로 검사 호출을 유지합니다. 새3m 경로는 추가 반경/높이 인자를 사용하고, 기존 기본값0.6m/1m는 그대로입니다.

3m 씬의 기존 큐브는 #16 / PR #57에서 실제 LootChest에 연결했습니다. 타일 한 변의40%인1.2m 정육면체를 평지/절벽 타일 중앙에7% 확률로 최대1개 배치합니다. 계단에는 배치하지 않으며 바닥 지지·중복/충돌을 확인합니다. 이 경로는 기존 중앙 통로 예약 대신 주변 보행 공간의 실제 도달성을 검사합니다. 배치 후 실제 경로도 검증합니다. 기존1m 소품·루팅 동작은 단위 회귀에서 확인합니다. 이전 큰 원형 비교는 기존 알고리즘의 회귀용이며 새3m 생성 규칙을 적용한 게임 필드로 간주하지 않습니다. 해당 비교 모드의 소품도 동일 루팅 연결을 사용합니다.

## 검증 진입점 및 이전 검증 이력

`TerrainIntegrationValidation.Run`은 같은 저장 씬의 현재 규격을 확인해3m 검사로 연결합니다. 실제 Play 검사는 `TerrainIntegrationPlayVerification.Run` 또는 `MicroTerrainPlayVerification.Run`이며 같은 씬을 엽니다. 독립 원형/소품 단위 검사는 임시 물리 씬에서 실행합니다.

- 생성 단계에서 최소116,640개 NavMesh 경로 검사, 소품 배치/정리 후 같은 검사 추가 수행.
- 고립된2m 절벽은 거부하고0→1→2m 계단 경로는 허용하는 실제 원형 fixture.
- 실제 캡슐의0→1→2m 왕복과 절벽/외곽 벽의 달리기·점프 차단.
- 기존 생성기100seed×2, 승인 원형436상태/228왕복, 이전 전체 폭 원형160왕복 회귀.

근거는 로컬 `UnityProject/Artifacts/micro-final-validation.log`, `micro-play.log`, `micro-legacy-props.log`, `micro-terrain-results.txt`, `micro-play-results.txt`, `micro-*.png`에 기록합니다. Windows 빌드·몬스터/실제 필드 상자 통합·대규모 성능 프로파일링은 별도입니다. 벽 제거 후 절벽 외형·중앙 상자·고저차와 계단의 자연스러움은 사람 재검토가 필요합니다.

## 통합 씬의 실제 상자 루팅 (#16 / PR #57)

기존 `TerrainIntegration.unity`의 플레이어에 PlayerInventory·PlayerInteraction을 저장하고, 최종 소품 도달성 복구 후 남은 큐브에만 LootChest를 연결합니다. 기존7%·타일 중앙·1.2m 큐브·Collider·보행 공간 조건은 유지합니다. 세대 ID와 상자 순번으로 고유 ID를 부여하고, 기존 큐브 중심을 상호작용점으로 사용합니다. 상자는 각각 검토용 Scrap10개를 가지며 외형과 Collider는 빈 상자도 유지합니다.

- 가까운 상자에서 **E**로 획득합니다. 하단 HUD는 실제 Scrap 합계·슬롯·방금 사용한 상자의 잔여/Empty 상태를 표시합니다.
- **F**는 Scrap96/99·칼19개로 인벤토리를 채우는 검토 도구입니다. F → E로3개 획득/7개 잔여 → **V**로 Scrap 공간 확보 → E로7개 회수를 확인합니다. 기존 G 갤러리 조작은 유지합니다.
- **R/T/L/P**로 필드를 재생성하면 이전 상자는 비활성화·삭제되고 새 배치 상자는10개로 초기화됩니다. 플레이어 인벤토리는 유지합니다. 이는 반복 검토용 필드 초기화이며 저장/경제/재방문 보존 규칙이 아닙니다.
- 전용 미저장 검토 장면을 만들 필요 없이 `Nomad > Terrain > Open Integration Test Scene`에서 Play합니다. Rebuild에도 동일 연결을 적용합니다.
- #18의 지속 NavMesh/Ready/스폰 계약과 #20의 정식 랜덤 상자 정책·전투 흐름은 별도입니다. 이번 연결로 다른 임의의 씬까지 자동 구성되는 것은 아닙니다.

`Nomad.Loot.Editor.TerrainLootVerification.Run`은 저장 씬에서 실제 E/F/V/T/P 입력, 부분3+7·빈 상자·기존 Collider 유지·동일 seed 배치/새 상자 수량·이전 세대 정리·인벤토리 유지·HUD를 검사합니다. 성공 표식 `TERRAIN_LOOT_PASS`, 로그 `Artifacts/terrain-loot-play.log`, 캡처 `terrain-loot-player.png`와 `terrain-loot-overview.png`입니다. 기존 통합 Play 검증 진입점도 유지합니다.
