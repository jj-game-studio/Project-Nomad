# 1차 공통 조작·지형·시스템 연결 규격

- 기준 이슈: [#10](https://github.com/jj-game-studio/Project-Nomad/issues/10)
- 적용 범위: 1차 구현의 공통 기준. 게임 기능 구현은 각 하위 이슈에서 진행합니다.
- A: VirtualExplorer7613 — 캐릭터·플레이어 전투·공통 피해 처리·인벤토리. B: PortalCube — 지형·생성·상자. 몬스터: Lemonade8080 — 몬스터 행동·랜덤 배치·전투 통합 (#17·#19). 기존 공용 규격을 유지하며 소유 영역 변경은 해당 담당자와 조율합니다.

## 현재 유효한 합의와 초기 구현 규격 (2026-11-13)

합의 출처: [사용자 직접 지시 및 두 팀원 공동 합의·위임 기록](https://github.com/jj-game-studio/Project-Nomad/issues/10#issuecomment-6845304226).
두 팀원은 직접 지시와 세부 규격 결정 위임에 합의했습니다. 아래 수치·형식은 위임받은 에이전트의 초기 결정이며 플레이 검증 완료를 뜻하지 않습니다. 공용 규격 변경은 이 Issue에 기록하고 양쪽 구현에 반영합니다.

### 1. 이동·카메라·공격
- WASD 카메라 수평 방향 기준 이동, 대각선 속도 정규화. Space 점프, 왼쪽 Shift 구르기, 좌클릭 1회 공격, E 공통 상호작용, Tab 인벤토리 표시.
- E는 상자뿐 아니라 상호작용 가능한 대상에 사용하는 공통 키입니다.
- 왼쪽 Shift 구르기: 거리 3m, 지속 0.3초, 재사용 대기 1초(시작 시점 기준). 접지 상태에서만 시작하며 이동 입력 방향, 입력이 없으면 캐릭터가 바라보는 수평 방향으로 진행합니다. 대기 시간은 게임 시간 기준이며 일시정지 시 멈춥니다.
- 구르기 동작 중 전투 피해는 무효화합니다. 피격 판정은 발생해도 체력 감소·피격 경직·넉백을 적용하지 않습니다. 지형 충돌은 유지하며 벽을 만나면 이동만 멈추고 남은 동작 시간 동안 무적은 유지합니다. 공중으로 이탈하면 구르기와 무적을 종료하고 낙하로 전환합니다.
- 구르기 중 재구르기·점프·공격·상호작용은 불가하며 입력을 예약하지 않습니다. 낙하 피해와 맵 밖 추락 사망에는 구르기 무적을 적용하지 않습니다. A가 구르기 상태 및 공통 피해 판정을 담당합니다. 수치는 초기 기준이며 플레이 검토로 조정합니다.
- 카메라는 플레이어를 고정 대상으로 추적합니다. 초기 오프셋 (0, 12, -8)m, 플레이어를 바라보는 고정 회전, 원근 FOV 50도. 사용자 회전·줌·독립 이동은 없습니다. 플레이어 회전에 카메라가 회전하지 않습니다.
- 좌클릭 시 화면 좌표에서 카메라 레이를 최대 200m 발사하고, 가장 가까운 지형·장애물·피해 대상 표면의 충돌점을 조준점으로 저장합니다. 자기 충돌체·트리거·장식 전용 충돌체는 제외하고 UI 위 클릭은 공격하지 않습니다. 유효 충돌점이 없으면 발사하지 않습니다.
- 총알·마법은 발사구에서 조준점 방향으로 진행합니다. 카메라 레이는 조준용이며 직접 피해 판정에 사용하지 않습니다. 실제 발사체의 첫 충돌에서 막히고, 피해 대상이면 한 번 피해를 적용합니다. 초기 관통·유도 없음.
- 빠른 발사체는 이전 위치와 다음 위치 사이의 충돌을 검사하여 얇은 벽을 통과하지 않게 합니다. 발사구가 벽 내부이면 발사를 차단합니다. 높은 적·낮은 적·난간 뒤 적·카메라에는 보이지만 발사구 앞이 막힌 경우를 검증합니다.

### 2. 캐릭터·통행
- Unity 1 unit = 1m, Y 위, XZ 바닥. 초기 캐릭터 캡슐 높이 1.8m·반지름 0.35m, 이동 5m/s, 최대 경사 45도, 단차 0.3m.
- 점프 최고 상승량 1.2m, 중력 20m/s². 접지 상태에서만 점프하며 공중 추가 점프 없음.
- 초기 최대 체력 100. 공중 구간 최고 발 위치부터 착지 발 위치까지 낙차를 측정하고 3m 이하는 무피해, 초과하면 ceil((낙차-3)×10) 피해를 착지 시 한 번 적용합니다. 점프 상승분도 포함하며 생성·순간이동은 측정을 초기화합니다.
- 필수 경로의 유효 폭 2m 이상·머리 위 여유 2.2m 이상. 계단 한 단 높이 0.25m 이하, 경사로 45도 이하.
- 초기 적 경로는 점프·위험한 낙하 없이 왕복 가능한 경로로 만듭니다. 플레이어 점프·낙하는 부가 이동으로 허용합니다. 맵 밖 추락은 사망 처리합니다.

### 3. 사각 지형 타일
- 기본 점유 면적 10×10m 정사각형, 배치 격자 10m, 수직 높이 간격 2m. 수평 타일 외에도 동일 면적 안에서 높이를 연결하는 계단·경사 타일을 허용합니다.
- 타일 루트 원점은 XZ 중앙·하단 기준 높이, 배율 (1,1,1), Y축 90도 단위 회전만 허용합니다.
- 연결 지점은 변 중앙, 통로 바닥 높이에 둡니다. 로컬 +Z는 바깥 방향, +Y는 위. 연결 시 위치·높이는 일치하고 바깥 방향은 서로 반대여야 합니다. 기본 연결 폭 2m·유효 높이 2.2m.
- 모든 타일이 네 방향으로 연결될 필요는 없습니다. 연결점별 위치·방향·폭·높이·유형을 명시하며 계단 상단/하단 연결점은 다른 높이를 가질 수 있습니다.
- 점유·충돌 검사 영역을 타일에 명시합니다. 경계 접촉은 허용하되 지형 내부 관통은 금지합니다. 위치 허용 오차 0.01m·방향 오차 0.1도. 연결부 예외는 지정된 좁은 연결 영역에만 적용합니다.
- 타일당 배치 후보 최대 50회, 필드 전체 재생성 최대 3회 후 실패를 반환합니다. 실패한 필드를 플레이 가능 상태로 공개하지 않습니다.
- 구매 애셋과 포함 프리팹은 비공개 애셋 저장소, 생성 로직은 공개 프로젝트에서 관리합니다.

### 4. 인벤토리
- 아이템은 불변 문자열 itemId로 식별하고 정의에 표시 이름·최대 중첩 수를 둡니다. 수량은 양의 정수입니다.
- 초기 20슬롯, 일반 재료 최대 중첩 99, 무기·방어구 1. 무게 제한 없음. 장비 장착·경제·창고는 별도 작업입니다.
- Add(itemId, requestedCount)는 실제 추가 수량을 반환합니다. 기존 같은 아이템 스택부터 채우고 빈 슬롯을 사용합니다. 공간 부족이면 가능한 만큼만 넣습니다.
- Remove(itemId, requestedCount)는 실제 제거 수량을 반환합니다. 부족하면 보유량까지만 제거합니다. 알 수 없는 ID·0 이하 수량은 변경 없이 0을 반환합니다.
- 성공적으로 변경한 뒤 변경 알림을 한 번 보내 UI가 보유 목록과 수량을 갱신합니다. 동일 입력으로 중복 추가하지 않습니다.

### 5. 상자 상호작용
- A: E 입력·대상 탐지·인벤토리 제공. B: 상자의 보유 목록·상호작용 처리·열림/빈 상태 표시.
- 발 위치 기준 거리 2m 이내이며 플레이어 몸통에서 상자 상호작용점까지 장애물에 가리지 않은 상자 중 가장 가까운 하나를 선택합니다. 같은 거리면 고유 ID 순으로 결정합니다.
- E 1회에 상자 목록 순서대로 전량 획득을 시도합니다. 각 항목에서 Add의 실제 반환량만 상자에서 차감합니다.
- 공간 부족·빈 상자에서는 남은 아이템을 보존하고 안내합니다. 처리 중 재진입을 막고 입력 1회에 1회만 처리합니다. 부분 루팅 후에도 상자는 유지합니다.
- 공용 상호작용 계약은 CanInteract(context), Interact(context)로 하고 context에 플레이어·인벤토리를 전달합니다. A가 계약을 제공하고 B가 상자에 구현합니다.

### 6. 생성 결과 전달
- 생성 순서: 지형 연결 → 통로를 막지 않는 소품 배치 → 이동 경로 준비·도달성 및 생성 지점 검증 → Ready 결과 → A의 적 배치 / B의 상자 배치.
- B가 GenerationResult를 제공합니다: generationId, seed, 성공 여부, 실패 사유, 플레이어 시작 위치·회전, 적/상자 생성 지점 목록(고유 ID·위치·회전·허용 반경).
- 상태는 Generating / Ready / Failed. Ready는 이동 경로 및 지점 검증까지 끝났다는 뜻입니다. 상태 조회와 마지막 결과 조회를 제공하여 늦게 연결된 시스템도 결과를 받습니다.
- 각 generationId당 완료/실패 통지는 한 번, 소비자도 generationId로 중복 배치를 막습니다. Failed에서는 적·상자를 생성하지 않습니다.
- 재생성 전에 A는 이전 적·발사체, B는 이전 상자·생성 지형을 정리합니다. 이전 결과를 무효화하고 새 generationId로 시작하며 완료 전 플레이어 입력을 잠급니다.

### 7. 경로·생성 지점 책임
- B는 생성 지형과 소품 반영 후 초기 적 크기(캐릭터와 같은 캡슐)에 맞는 이동 경로를 준비하고, 시작점에서 필수 연결부·적 지점·상자 접근점으로 도달 가능한지 검증합니다.
- 초기 적 경로 방식은 Unity AI Navigation의 NavMesh를 기준으로 합니다. 패키지·프로젝트 설정 추가는 B가 사전 공개하고 A와 중복 변경을 피합니다.
- 적 지점은 벽·지형과 겹치지 않고 반지름 0.5m 여유를 확보하며 시작점에서 5m 이내는 제외합니다. 상자 지점은 반지름 0.75m 점유 공간과 2m 이내의 도달 가능한 상호작용 접근점을 확보합니다.
- A는 제공된 적 지점 안에서 적 수량·선택·개체 배치를 담당하고, B는 제공된 상자 지점 안에서 상자 배치를 담당합니다. 공간이 부족하면 유효 지점 수만큼 줄이며 재사용·겹침·무한 재시도를 하지 않습니다.
- B는 적/상자 지점의 점유 영역이 서로 겹치거나 필수 통로를 막지 않도록 제공합니다. 플레이어 점프·낙하 가능성과 적 NavMesh 이동 가능성은 별도로 검증합니다.

## 구현 시 검증 기준

- 평지 → 계단 → 2m 높은 평지를 플레이어와 적이 왕복합니다.
- 점프·3m 초과 낙하 피해·맵 밖 추락 처리를 확인합니다.
- 높은 대상·낮은 대상 조준과 실제 발사 궤적의 장애물 차단을 확인합니다.
- 상자 10개 중 3개만 들어가면 7개가 남으며 반복 입력으로 복제되지 않습니다.
- 생성 실패·공간 부족·재생성에서 무한 반복과 중복 배치를 방지합니다.
- 구르기 거리·지속·재사용 대기, 벽 충돌·공중 이탈, 동작 중 전투 무적 및 낙하 피해 예외를 확인합니다.

현재 문서는 합의와 위임에 따른 초기 규격이며 Unity 구현·플레이 검증 완료를 뜻하지 않습니다. 후속 수치 조정과 공용 계약 변경은 #10에 기록합니다.
