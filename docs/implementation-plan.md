# 단계별 구현 목표와 작업 분담

- 대상 플랫폼: Windows 11
- 개발 환경: Unity 6000.6.9f1 / Universal 3D(URP)
- 상위 이슈: [#4](https://github.com/jj-game-studio/Project-Nomad/issues/4)
- 게임 규칙: [게임 기획서](game-design.md)

## 단계별 목표

### 1차: 필드 전투·파밍·게임플레이

- 캐릭터 이동과 인벤토리 시스템을 구현합니다.
- 필드에 랜덤한 지형·소품을 배치합니다.
- 파밍 상자를 랜덤 배치하고 아이템을 획득할 수 있도록 합니다.
- 몬스터 시스템을 구현합니다. 플레이어 탐지·추적·공격, 피해·사망 처리 연결, 필드 랜덤 생성·배치와 캐릭터와의 교전을 포함합니다.

필드는 POLYGON Dungeon Realms 애셋으로 미리 제작한 지형 조각을 랜덤 생성 시 연결해 구성합니다. 조각에는 바닥 높낮이가 있을 수 있으며, 계단·경사로를 포함한 이동 경로를 연결합니다.

### 2차: 마을과 필드를 연결하는 한 사이클

- 돌아다닐 수 있는 마을 맵을 구현합니다.
- 아이템을 돈이나 더 강한 아이템으로 교환합니다.
- 여관에서 HP를 회복하는 등의 캐릭터 정비를 구현합니다.
- 일차와 낮·밤 시간 시스템을 구현합니다.
- 필드 탈출구로 나가면 마을로, 마을의 필드 입구로 나가면 필드로 이동합니다.
- 이동은 장면 전환으로 연결합니다.

### 3차: 여러 필드와 마을로 구성된 월드

- 월드 맵 중앙에 시작 마을을 배치합니다.
- 여러 필드와 마을을 군데군데 배치하고 연결합니다.
- 나머지 세부 목표는 추후 추가합니다.

### 4차: 시세 변동

- 판매량·구매량에 따라 마을별·아이템별 시세를 조정합니다.
- 3일마다 기본 시세를 갱신합니다. 기획서의 1일차 최초 적용, 4·7·10일차 아침 전 지역 갱신 기준을 따릅니다.
- 거래량 누적·초기화와 가격 계산식은 별도 결정합니다.

판매량·구매량 반영은 구매량만 집계하던 기획서 v0.3 이후의 변경 사항입니다. 이 항목은 최신 사용자 지시를 따르며, 기존 기획서의 구매량만 집계한다는 문구보다 우선합니다.

## 1차 목표의 담당자와 검토자

| 역할 | 담당자 | 담당 범위 | 검토자 |
| --- | --- | --- | --- |
| A | VirtualExplorer7613 | 캐릭터·카메라·플레이어 전투·공통 피해 처리·인벤토리 | VirtualExplorer7613 |
| B | PortalCube | 지형 조각·필드 생성·소품·파밍 상자·생성 경로 | PortalCube |
| 몬스터 | Lemonade8080 | 몬스터 행동·피해·사망 연결·랜덤 배치·전투 통합 | PortalCube |

일반 PR은 작업자를 검토 담당자로 지정합니다. 팀원 전원 합의가 필요한 사안은 위 표의 기본 지정 대신 모든 팀원을 검토 담당자로 지정합니다. PR 작성자 본인의 Reviewers 지정이 불가능한 경우에는 AGENTS.md에 따라 검토 담당자와 사유·승인 결과를 기록합니다.

필드 생성 작업량을 고려해 인벤토리는 A가 담당합니다. 2~4차의 세부 분담은 각 단계 작업 분할 시 정하며, 현재 역할을 자동으로 확대 적용하지 않습니다.

몬스터 작업은 기존 #17·#19를 Lemonade8080에게 이관합니다. #15의 플레이어 전투·공통 피해 처리는 A, #18의 경로·유효 생성 지점 제공은 B가 유지합니다. 몬스터 종류·수치·난이도는 별도 결정하며, 이번 배정으로 확정하지 않습니다.

단계 번호는 통합 점검 순서입니다. 실제 착수는 각 구현 이슈의 선행 작업을 기준으로 하므로, 준비된 독립 작업은 병렬 진행할 수 있습니다.

## 지형 조각과 시스템 연결 규격

다음은 0단계에서 수치와 형식을 합의할 설계 항목입니다.

- 연결 지점: 위치·방향·통로 폭·높이와 연결 가능 유형.
- 배치 영역: 다른 조각과의 겹침을 검사할 범위.
- 이동 경로: 입구와 출구 사이를 플레이어와 적이 이동할 수 있는 경로.
- 생성 지점: 적·상자·소품을 배치할 수 있는 위치와 금지 영역.
- 생성 순서: 지형 연결 → 소품 배치 → 이동 경로 준비·검증 → 적·상자 배치.
- 아이템 획득: 추가 요청에 실제 추가 수량을 반환하고 나머지는 상자에 유지.
- 상호작용: A가 입력·대상 탐지를, B가 상자 동작을 담당.
- 배치 실패: 재시도 한도를 두고 실패 결과를 반환. 무한 생성 반복 방지.

첫 공동 검증은 평지 → 계단 → 높은 평지를 연결해 캐릭터와 적이 왕복하는 것입니다. 다른 높이의 적에 대한 조준·명중도 초기 전투 검증에 포함합니다.

## 파일 소유와 제출

- A: 플레이어·카메라·무기·공통 피해 처리·인벤토리 코드/프리팹, A 테스트 씬, 최종 통합 씬.
- B: 필드 생성·지형 조각·상자·소품 코드/프리팹과 B 테스트 씬.
- 몬스터 담당: 몬스터 코드/프리팹과 전용 테스트 씬. A 소유 통합 씬과 공통 피해 처리, B 소유 생성 경로를 수정할 때는 해당 담당자와 먼저 조율합니다.
- 패키지·프로젝트 설정·공용 규격 변경은 사전 조율합니다.
- 각자 테스트 씬에서 개발하고 상대 소유 씬·프리팹을 동시에 수정하지 않습니다.
- 구매 애셋과 구매 애셋을 포함하는 지형 조각은 라이선스를 확인해 비공개 애셋 저장소에서 관리합니다. 생성 로직은 공개 프로젝트에서 관리합니다.
- 애셋 커밋을 먼저 푸시한 뒤 메인 저장소에 서브모듈 참조를 기록합니다.
- 각 작업은 별도 브랜치와 PR로 제출하고 상대 담당자가 검토합니다. 선행 조건이 미충족된 이슈는 착수 가능으로 간주하지 않습니다.

미니맵·시세 지도 등 기획서의 나머지 기능은 삭제된 것이 아니며, 현재 1차 작업 목록에서 다루지 않습니다. 후속 배정 시 포함할 단계를 정합니다.
