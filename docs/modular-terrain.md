# 공용 지형 타일 (#50)

## 구성

구매 에셋을 복제하지 않고 Unity 기본 Cube 메시를 공유하는 원형 3개를 제공합니다. 모든 치수는 기존 10m 타일/높이 0·2m/단 높이 0.25m/캐릭터 반지름 0.35m·높이 1.8m 규격을 따릅니다.

- `ModularCross`: 중앙 4×4m 참과 네 계단 팔, 코너 3×3m 바닥 4개.
- `ModularTee`: 남·동·북 계단 팔, 서쪽 막힌 3×10m 영역 1개와 동남/동북 3×3m 코너 2개. 세 영역 구분은 사용자 확인을 받았습니다.
- `WideStairs`: 전체 10m 폭의 일자 계단. 남쪽 0m 참 → 8단 → 북쪽 2m 참으로 이어집니다.

좌표는 +Z=북, +X=동입니다. 코너 바닥은 `None / Low(0m) / High(2m)` 중 하나만 활성화됩니다. 바닥 Renderer·Collider·외곽 연결점을 같은 그룹에 두며, 비활성 연결점은 `TerrainPiece.Connections`에서도 제외합니다. 점유 AABB는 10×2.25×10m로 보수적으로 유지합니다. 바닥이 없는 코너에 다른 타일을 끼워 넣는 방식은 지원하지 않습니다.

## 조합과 생성기 연계

`ModularTerrainTile.ApplyCombination(int)`을 배치 전에 호출합니다. 매 프레임 갱신은 없습니다. 번호는 영역 0이 최하위 자리인 3진수입니다. 각 자리는 0=없음, 1=낮음, 2=높음입니다.

| 원형 | 영역 순서 | 번호 |
| --- | --- | --- |
| 십자 | 남서, 남동, 북동, 북서 | 0~80 |
| T자 | 서쪽 막힌 영역, 남동, 북동 | 0~26 |

따라서 전부 낮음은 십자 40/T자 13, 전부 높음은 십자 80/T자 26입니다. 지원 범위를 벗어나는 번호는 예외로 거부하며 상태를 변경하지 않습니다. 회전은 루트 Y축 0/90/180/270도로 적용합니다.

외곽 연결점은 기존 `Walk`/2m 폭/2.2m 머리 여유 규격을 유지합니다. 코너에는 닿는 외곽 변별 연결점이 있습니다. 넓은 계단은 전체 폭으로 이동할 수 있으나 양 끝의 연결 정보는 x=-3.5/0/3.5m의 2m 통로 세 개로 표현합니다. 이는 연속 10m 폭 포트 하나로 계약을 변경하지 않기 위한 선택입니다. 계단 팔 입구 0m 포트는 첫 0.25m 단으로 연결됩니다.

#51에서는 `(원형, 조합 번호, 회전)`을 논리 후보로 사용하고 후보 선택 전 해당 조합의 연결 상태를 계산해야 합니다. 기존 생성기의 목록에 원형 2개만 넣으면 모든 108조합이 생성되지는 않습니다. 이번 PR은 생성기·WFC·NavMesh 준비(#18)·소품·상자를 변경하지 않습니다. 높은 코너 바닥과 낮은 계단 측면 사이에는 2m 단차가 있을 수 있으므로 포트 이외의 임의 경계가 모두 보행 가능하다고 간주하지 않습니다.

## 검토 방법

Unity 6000.6.9f1에서 `Nomad > Terrain > Modular` 메뉴를 사용합니다.

1. 제출된 프리팹은 `Assets/Nomad/Terrain/Modular/Prefabs`에 있습니다. `Create Shared Tile Prefabs`는 원형을 재생성하므로 원형을 직접 편집한 후에는 덮어쓰기에 주의합니다.
2. `Open All 108 Combinations`: 모든 조합을 12열 갤러리에 나열합니다. Scene 탭에서 비교하고 타일을 선택합니다. Gallery는 검토 전용으로 108개 인스턴스를 배치하며 실제 생성 필드의 성능 측정 장면이 아닙니다.
3. 선택한 타일 Inspector에서 조합 번호 또는 각 영역의 None/Low/High 선택으로 상태를 바꿉니다. 두 입력은 동기화되며 변경은 실행 취소와 장면 저장을 지원합니다.
4. `이 조합으로 플레이 검토 장면 열기`: 선택한 조합과 각 포트에 맞는 인접 바닥, 기존 PlayerMovement·TopDownCamera를 재사용한 검토용 플레이어를 배치합니다.
5. Play → Game 탭 클릭 후 WASD/Space/왼쪽 Shift로 이동합니다. 초기 위치는 첫 포트 외부 바닥입니다. 구멍으로 떨어지면 Play를 종료하고 다시 시작합니다.
6. Cross/Tee/Wide Stairs Playground 메뉴로 기본 검토 장면을 열 수도 있습니다. 기존 장면의 미저장 변경은 저장 확인을 거칩니다. 장면은 미저장 상태로 열리며 기존 통합 씬을 수정하지 않습니다.

## 검증

`Validate All Combinations`는 저장된 실제 원형 3개를 읽고 108개 조합+넓은 계단의 4회전을 검사합니다. 각 영역의 바닥 유무·높이·외형 활성 상태와 활성 포트의 바닥 지지를 확인하고, 대표 없음/낮음/높음 조합에서는 0.35m/1.8m 캡슐이 각 연결부를 왕복합니다. 넓은 계단은 양쪽 가장자리를 포함한 바닥 연속성을 검사합니다. 결과는 `Artifacts/modular-tiles-results.txt`에 기록합니다.

전체 실행: `unity run ./UnityProject --timeout 600 --log-file ./UnityProject/Artifacts/modular-run.log --no-tail -- -executeMethod Nomad.Terrain.Editor.ModularTileValidation.Run`

정확한 빌드 용량·런타임 메모리·대규모 필드 FPS는 별도 프로파일링이 필요합니다. 비활성 자식도 메모리는 사용하며 원형 수 감소를 FPS 개선으로 단정하지 않습니다. Windows 플레이어 빌드, WFC 생성 필드 통합, 아트/이동감의 최종 사람 수용은 자동 검증과 별개입니다.

## 제출 검증 결과 (2026-11-16)

- Unity 6000.6.9f1 실제 저장 프리팹 3종: 436개 회전 상태 검사와 228회 캡슐 왕복 통과. 계단 팔은 중앙 참까지, 넓은 계단은 전체 길이를 왕복하며 착지 바닥도 확인했습니다. 전체 실행 종료 코드 0.

- 십자/T자/넓은 계단/108개 갤러리 실제 카메라 렌더를 확인했습니다. 이미지와 결과는 로컬 `UnityProject/Artifacts/modular-*.png`, `modular-tiles-results.txt`, `modular-play-results.txt`에 있습니다.

- Unity 자동 직렬화로 변경된 DynamicsManager는 이 작업 사본의 실행 전 값으로 복원했으며 프로젝트 설정은 제출하지 않습니다. 기존 작업 사본/서브모듈의 미커밋 변경은 건드리지 않았습니다.
- Windows 플레이어 빌드, 실제 생성 필드 통합, 사람의 외형·영역 구분·이동감 수용 판단은 남아 있습니다.
